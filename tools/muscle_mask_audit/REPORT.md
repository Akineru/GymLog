# 肌群遮罩质量检查（只读）

检查时间：2026-10-14。只读加载正式 PNG，没有修改 Kotlin、Compose、Room、数据库、`muscle_manifest.json`、底图或任何正式遮罩。

配置来源是 `muscle_manifest.json` 的 33 条，以及 `MuscleMaskCatalog` 的 33 个应用肌群。两边是同一套资源。应用里的 `deltoid_lateral` 使用文件 `deltoid_middle.png`，清单 id 是 `deltoid_middle`，只计 1 个肌群。

底图 `muscle_front_base.png`、`muscle_back_base.png` 都是 1024×1536、带透明通道。alpha&lt;16 的像素是插画的透明背景，包括肢体之间的空隙。越界指遮罩不透明像素落在这块透明背景上，不是把所有透明像素都当成“人体外部的未知区域”。

遮罩不透明阈值：alpha≥200。16–199 记为边缘半透明，不计入不透明总数。碎片：4 连通域，面积&lt;64 像素算碎点。

轮廓是否贴合插画，不能由面积或像素比例单独下结论。标成 A 的，是本轮看过预览、没有明显越界和异常重叠、形状大体落在对应肌肉上。A 只表示暂时可接受，不是解剖学验证。没有逐张看过、指标又不够成明确几何错误的，标为 C。

## 哪些能批量做，哪些必须人工看

没有可以安全地批量自动重绘或批量改正式文件的项。

越界不能靠“裁到人体不透明区”修。那样外缘会变成躯干剪影，背阔肌第一阶段已经看到这个问题。也不能为了让重叠下降去整体缩小遮罩。

可以反复跑的，只有这次这种只读度量：尺寸、透明像素、越界比例、连通域、重叠比例。

必须人工确认的：

- 每一块的真实肌界，尤其是下缘、内缘，以及外缘是否只是身体剪影。
- 重叠里哪些是邻接，哪些是串色。臀中肌与臀大肌、缝匠肌穿过大腿，都属于这一类。
- 股四头肌合成遮罩与三头的包含关系可以保留，但它盖住缝匠肌和内收肌的部分要单独定规则。
- 四个空遮罩保持留空，除非以后改清单。不要自动补到邻近肌肉上。

## 建议的处理顺序

排序依据是：可见面积、越界或串色是否会让高亮看起来错位、以及是不是一整组互相覆盖。

1. 背阔肌。越界 25.8%，形状是光滑块，并且吞进大圆肌。校准稿已经在 `tools/lat_mask_preview/vector/`，还没替换正式文件。
2. 大腿前侧一组：股四头肌、股直肌、股内侧肌、缝匠肌、内收肌。合成遮罩和邻肌叠在一起，股内侧肌和内收肌还有明显越界。股外侧肌暂时可接受，但改合成遮罩时要一起看。
3. 肩和上背：三角肌中束、三角肌前束、斜方肌上部。中束和上斜方肌越界都超过 24%。
4. 腹外斜肌。越界 26.7%，下缘提前结束。
5. 前臂：肱桡肌、屈肌群、伸肌群。伸肌群正面完全落在肱桡肌里。
6. 背部余下的重叠：斜方肌中部、斜方肌下部、大圆肌、竖脊肌。竖脊肌还有大段没画到。
7. 肱三头肌。越界 11.8%。
8. C 类五块先不要改，等人工看预览：三角肌后束、腘绳肌、臀中肌、比目鱼肌、胫骨前肌。
